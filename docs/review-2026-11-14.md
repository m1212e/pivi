# Codebase review — 2026-11-14

Scope: security, correctness, best practices, and whether hand-rolled implementations should be replaced by libraries. Reviewed at commit `75901b2`.

The design is sound, but there is one critical and several high-severity hole, most of them small fixes. The code behind every critical and high item was read directly; several were also reproduced with small harnesses, but nothing was run against the real server.

## Critical

**The LAN filter can be bypassed with `..`** (`deploy/pivi-server.mjs:59-66`). The allowlist tests the raw `req.url`, but SvelteKit then normalises the path, so `/remote/../api/graphql` passes the filter and routes to `/api/graphql`. From any device on the Wi-Fi (or the `pivi-setup` hotspot):

- **Pairing token theft:** `curl --path-as-is 'http://<tv>:3000/remote/../api/graphql?query={pairing{pairingToken}}'` returns a valid token. With no phone connected there is no approval step, so the attacker gets full remote control.
- **No authorisation behind the filter:** `mustBeLoggedIn` is defined in `src/api/context.ts:11` and never called anywhere.
- **Mutations over GET:** `graphqlQuery` in `src/api/graphql.remote.ts` is a GET remote function that executes any client-supplied operation. That puts `installApp` (arbitrary container image) and `connectWifiNetwork` in reach. This step was read, not exercised.

Fix: decide on `new URL('http://x' + req.url).pathname` and 404 any raw target containing `..`, `%2e`, `\` or `//`. Reject non-query operations in `graphqlQuery`. As a backstop, refuse non-`/remote` routes from non-loopback clients in `hooks.server.ts`.

## High

- **One bad WebSocket frame crashes the server** (`src/api/ws/relay.ts:423`). Sockets have no `error` listener, so an oversized or invalid frame on port 5175 exits Node. This is reachable pre-auth from the LAN, and each crash logs out the active profile.
- **A 4-byte "webm" hangs the event loop forever** (`src/api/apps/containerIndex.ts:125-133`). `vintWidth` loops endlessly when the size byte is past the end of the buffer. systemd won't restart it because the process is alive.
- **An app exiting mid-request crashes the server** (`src/api/apps/runtime.ts:405-481`). `onExit` closes the reader without rejecting pending requests; on timeout, `void stopIfHung()` throws "Connection is closed" as an unhandled rejection.
- **`ORIGIN=""` in the Nix unit makes the server throw at import** (`nix/module.nix:394`). adapter-node 6.0.2 rejects an empty `ORIGIN`; this came in with the 2026-11-13 dependency update. CI only checks that files exist, so it didn't catch it. Confirm with a fresh build.
- **ffmpeg can be steered to loopback and LAN hosts** (`src/routes/api/stream/[appId]/[sessionId]/+server.ts:34-38`). The input format isn't pinned and the relay forwards the upstream `content-type`, so an app's CDN can serve an HLS playlist whose segments ffmpeg fetches itself, past the URL guard.
- **CSS injection through app image URLs** (`src/lib/components/MediaCard.svelte:58`). `style="--pivi-glow: url({image})"` interpolates the raw URL; `)` and `;` are legal in a path, so an app can add declarations. That lets it make the kiosk fetch any host and restyle the card. Use `style:--pivi-glow` with a quoted value.
- **Duplicate keys from apps crash host screens.** Keyed `{#each}` blocks use app-supplied ids (`VideoRow.svelte:26`, `OnScreenKeyboard.svelte:197`, `Select.svelte:214`). Svelte throws on duplicates in production and there is no error boundary. Two `en` subtitle tracks trigger it without malice.

## Medium

### Auth and relay

- PIN lockout is bypassable with parallel requests: the check runs before the scrypt await and the failure is recorded from a stale snapshot (`src/api/auth.ts:74-91`).
- The phone remote never reconnects after a drop; `createReconnector` is only used on the TV side.
- The relay has no ping/pong, so a vanished phone stays "connected" and blocks new pairings.
- The TV role is granted on loopback address alone, with no `Origin` check.

### App platform

- Unbounded reads: the registry client buffers the whole body before checking size (`registry.ts:166`), and the segment-index fetch accepts a plain 200.
- A registry can point the host at LAN URLs through the auth `realm` and redirects.
- An app can flood small messages and grow host memory without bound; the RAL maps `setImmediate` to a 1 ms timer.
- Update checks write back a stale row, so a permission revoked mid-check comes back. There is no per-app lock.
- No downgrade protection: any validly signed different digest counts as an update.
- First-party apps are unsigned: CI has no cosign step and suggested apps carry no key.

### Streaming and player

- The HLS rewriter's unanchored `URI="…"` regex leaves attacker URLs in the playlist (`hlsPlaylist.ts:87`).
- Direct playback 302s the browser to the raw CDN URL.
- Concurrent `setupPlayback` calls can leave two Shaka players on one `<video>`.

### System

- A failed nmcli connect can put the Wi-Fi password into the on-screen error (`wifi.ts:79-86`).
- The hotspot fallback is unconditional, sticky and uses a fixed passphrase.
- No `flake.lock` is committed.
- CI runs no tests, lint or type-check.
- There is no CSP anywhere.

### Apps

- Twitch: any transient refresh failure deletes the session (`apps/twitch/auth.ts:125`), and refresh isn't single-flight.
- YouTube: a top-level `await Innertube.create` kills the app when youtube.com is unreachable, there are no fetch timeouts, and live streams can't resolve.
- Manifests: `*.cloudfront.net` and `*.googleapis.com` include attacker-controllable hosts.

### UI

- The install preview re-grants switched-off permissions on any state push (`AppManagerPanel.svelte:69`).
- `Select` leaves the page inert if it unmounts while open.

## Hand-rolled vs library

Most of what was built in-house should stay; the changes worth making are few.

| Piece                                                    | Verdict                                                                                                                                                |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| LAN gatekeeper regex                                     | Change approach: serve the LAN listener from a static-only handler (prerendered `/remote` plus `/_app/immutable`), so no LAN request reaches SvelteKit |
| HLS playlist rewriter                                    | Replace the regex with `hls-parser` or a real attribute tokenizer; keep the HMAC link scheme                                                           |
| Wi-Fi join and hotspot                                   | Move to NetworkManager over D-Bus (`dbus-next`); keeps the password out of argv and gives real state signals. Keep nmcli for scan and status           |
| IP range classification in `urlGuard.ts`                 | Use `ipaddr.js` for NAT64, 6to4 and reserved ranges; keep the connect-time lookup design                                                               |
| PIN hashing                                              | Switch to `node:crypto` scrypt (off the event loop); small gain given a 4-digit space                                                                  |
| `drizzle-kit push --force` at boot                       | Replace with generated migrations before there is data worth keeping                                                                                   |
| Service worker                                           | Delete: it cannot run on an HTTP LAN origin and its scope misses `/remote`                                                                             |
| Version comparison                                       | Missing; add `semver` when adding downgrade protection                                                                                                 |
| Pairing protocol and encrypted channel                   | Keep: sound signed-ephemeral design on `@noble`, tested                                                                                                |
| cosign key verification                                  | Keep; use `@sigstore/verify` only if keyless signing is wanted                                                                                         |
| OCI registry client, SSRF guard, redirect follower       | Keep and harden                                                                                                                                        |
| sidx/Cues parser                                         | Keep, but add bounds checks and fuzz tests; it has no spec today                                                                                       |
| Shaka-based players, JSON-RPC glue, NDJSON               | Keep                                                                                                                                                   |
| Spatial nav, on-screen keyboard, Select, Slider, PinPad  | Keep: off-the-shelf components assume pointer or arrow-key focus models that don't fit                                                                 |
| Twitch GQL/IRC/OAuth, YouTube TV parsers, yt-dlp process | Keep; no maintained library fits better                                                                                                                |
| `dexie` for one record                                   | Optional swap to `idb-keyval`                                                                                                                          |

## What held up

- Pairing and reconnect crypto: no replay, reflection or key-swap path found.
- SSRF guard: connect-time address check, every redirect hop re-checked.
- Signature verification: digest binding is correct and it fails closed.
- Sandbox spec: no host mounts, no env, default-deny network.
- No `{@html}` anywhere; no shell in any child-process call.
- Kiosk runs without `--no-sandbox`; Postgres uses peer auth.

## Not determined

- Whether a sandboxed app can reach host loopback ports 3000 and 5175. If it can, the unauthenticated GraphQL and TV-role findings apply to apps too.
- microsandbox internals, including whether the VM outlives an exited app process.
- Whether `pinHash` is ever returned through GraphQL. Worth one test: `{ users(where:{pinHash:{like:"%"}}){id} }`.

About 60 further low-severity items (Dockerfile pinning, systemd hardening, accessibility, duplicated components, test gaps) are not listed here.

## Suggested order

Fix the LAN filter, the relay error handler, the vint loop, the app-exit rejection and `ORIGIN` first — each is a few lines.

## Implementation status

Done, committed and pushed, with `bun run check`, lint and the server tests passing. Nothing was run against a real server, kiosk, NetworkManager or Nix build.

- Critical and high: all fixed (LAN filter and loopback backstop, GraphQL operation type, relay `error` handlers, EBML bounds, app-exit rejection, `ORIGIN`, ffmpeg input formats, CSS injection, duplicate keys).
- Medium: PIN lockout serialised, relay heartbeat and `Origin` check, bounded registry reads, registry realm and redirects restricted to public addresses, app message-rate limit, HLS attribute parsing, Wi-Fi password redaction and D-Bus join, per-app operation queue, downgrade protection, install-preview toggles, `Select` inert restore, stale `forgetApp`, segment-index status and size, serialised playback setup, phone remote reconnect, random hotspot passphrase, YouTube lazy init with retries and timeouts, CSP, service worker retired, CI added.
- Library swaps: `ipaddr.js` (done), generated migrations (done), D-Bus Wi-Fi (done, nmcli fallback). `hls-parser` was tried and rejected: it drops Twitch's prefetch and live-sequence tags.

Not done:

- Manifest host wildcards (`*.cloudfront.net`, `*.googleapis.com`): needs the real host list from a live session.
- `flake.lock`, and refreshed Nix dependency hashes for the new dependencies.
- First-party apps are still unsigned: CI has no cosign step, which needs a signing key.
- Direct playback still 302s to the CDN. This is a deliberate speed trade-off, noted in the route.
- YouTube live streams still can't resolve (a feature gap).
- The remaining low-severity items, and the three "not determined" questions.
